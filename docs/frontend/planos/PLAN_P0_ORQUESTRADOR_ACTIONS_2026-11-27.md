## Design escolhido
Manifesto imutável por PR protegida, entrada append-only de request, sem comandos ou workflows arbitrários; validação local com Git e REST somente leitura; chamada literal a reusable workflow por workflow_call. Sem token externo, actions:write, segredos novos, workflow_run de código não confiável, auto-approve ou auto-merge. Os builds/regressões/CI já acionados por pull_request/push permanecem como estão. O novo transporte não é autoridade de certificação. O request contém schema, request_id UUID, repo, mission_id, operation enum, environment CODE, source_sha, source_pr, request_pr, plan_ref/blob, authorization_ref, predecessor_checkpoint_ref; sem campos de migração. Validar esquema fechado, identidade real e merge commit/pais/HEAD/base, revisão APPROVED elegível exata, ausência de review impeditivo posterior, checks do SHA, escopo de request e ancestralidade; erro/API indisponível => bloquear. Solicitação só após PLAN específico com caminho exato. Uma entrada adicionada por merge, nunca editada/removida. Repetição, branch não autorizada, workflow arbitrário, PROD, múltiplos manifests, dado extra, origem divergente, permissão ausente: FAIL-closed. Nenhum comentário autoriza por si.
Operações iniciais CANARY_CODE e TESTE_C_FULL_CODE (desabilitada até certificação). Para Teste C completo, preservar .github/workflows/contaos-teste-c-independente.yml blob bda4e338316faa259c571cdc5f65f03e7832bd77; eventual alteração aditiva a workflow_call para forçar execução completa apenas no request autorizado, sem alterar gatilhos/requisitos existentes, capturar SHA exato do commit executado, evidências e artefatos; se request-only commit, exigir identidade das fontes funcionais e não recarimbar certificado prévio. Testes administrativos read-only; nenhum novo uso de token backend. Inventariar workflows e classificar automáticos existentes, elegíveis read-only, privilegiados bloqueados ou futuros; habilitação futura requer PLAN próprio, não permitir dispatch genérico.
